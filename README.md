# Trivial Thursdays on WRFL — Cloudflare site

A replacement for www.trivialthursdays.com, which today redirects to a Blogger page. It runs as one Cloudflare Worker backed by a D1 database. There's no build step and no framework, so it's easy to extend.

## What's here

| Route | What it does |
|---|---|
| `/` | Home: intro, air time, Listen and Facebook Live buttons, the **next show** (with an "On air now" badge Thursdays 10–noon ET), and the next six shows |
| `/schedule` | Full season guest schedule. Past shows are dimmed. `?season=` switches seasons |
| `/calendar.ics` | Subscribable calendar feed, one event per show (10–noon ET) |
| `/api/episodes` | JSON schedule (`?season=`, `?from=YYYY-MM-DD`) for future integrations |
| `/admin` | Add, edit and delete shows and their lineups; edit site settings. **Protected by Cloudflare Access** |
| `/p/trivial-thursdays-on-wrfl-guest-schedule.html` | 301 → `/schedule` (the old Blogger path) |
| `/healthz` | Health check |

```
src/index.js     router, admin handlers, iCal
src/views.js     all HTML/CSS (template strings)
src/db.js        D1 queries
src/auth.js      Cloudflare Access JWT verification
migrations/      0001 schema, 0002 Fall 2026 seed (generated by scripts/build-seed.mjs)
```

**Data model:** each `episode` is one Thursday. It has an air date, a season, an optional headline and notes, and a published/draft flag. Each episode has ordered `segments`, and each segment has a kind (`guest` / `music` / `feature`), a name, an optional link and an optional note. `settings` is a key/value table for the tagline, links, logo and so on.

## Deploy

```bash
npm install
npx wrangler login
npx wrangler deploy          # → https://trivial-thursdays.<your-subdomain>.workers.dev
```

### Lock down /admin with Cloudflare Access (required before you can use the admin)

Until the two variables below are set, `/admin` returns 403.

1. Go to Zero Trust → Access → Applications → Add → **Self-hosted**.
2. Add a public hostname with path `admin*` on each hostname that serves the site (the workers.dev one and later trivialthursdays.com).
3. Add a policy that allows the emails of the people who edit the schedule.
4. Copy the application's **Audience (AUD) tag** and your team domain (`<team>.cloudflareaccess.com`).
5. Put them in `wrangler.jsonc` → `vars.ACCESS_AUD` / `vars.ACCESS_TEAM_DOMAIN`, then run `npx wrangler deploy` again.

The Worker checks the Access JWT itself: signature against the team's JWKS, plus audience, issuer and expiry. Admin form posts also get a same-origin check.

### Point the domain at it

After trivialthursdays.com's DNS is on Cloudflare, uncomment the `routes` block in `wrangler.jsonc` and deploy. That replaces the current Blogger redirect.

## Local development

```bash
echo 'DEV_ADMIN_BYPASS=true' > .dev.vars          # opens /admin locally only
npx wrangler d1 migrations apply trivial-thursdays --local
npx wrangler dev
```

## Known gaps / next improvements

- **Logo** is hotlinked from Blogger. Move it into the Worker (static assets) or R2, then update the logo URL in Admin → Settings.
- The Blogger page listed **Nov 5 twice**. The second one, after Nov 26, was an empty placeholder, so I didn't import it.
- The WRFL link on the Blogger page was broken (relative link). Here it points to https://wrfl.fm.
- Ideas: episode detail pages with audio archive links (R2), guest pages that link repeat guests (Uniting Voices, League of Women Voters), a guest request form (Turnstile + D1), past-season archives, and automatic "on air" from the station stream.
